# DESIGN v3.0 发散蓝图：The Living Actor（活体演员）

> 状态：**发散提案（未定案）** — 本文试图**跳出当前框架**，重新审视「LLM 驱动 Live2D」这个问题本身。
> 不是对 v0.1/v0.2 的增量修补，而是问一个更根本的问题：
> **「LLM 应该扮演什么角色，才能让 Live2D 栩栩如生？」**
>
> 一句话结论：**现在的框架让 LLM 当"提线木偶师"（每回合输出指令），
> 更优的设计是让 LLM 当"导演"（设定性格与意图），而让一个**连续运行的"身体"（动力学运动控制器）**负责每一帧。
> 角色从「被指令驱动的参数容器」变成「被意图/情绪持续浸润的生命体」。

---

## Part 0. 当前框架的 6 个隐含假设（以及它们为什么限制了你）

| # | 隐含假设 | 后果（为什么不够好） |
|---|---|---|
| A1 | **LLM 是决策者，输出离散指令**（play/face/set） | 指令是脆的：LLM 必须精确选对资产+覆盖，错了就崩/回退。错误被「二值化」——不是完美就是不执行 |
| A2 | **行为 = 关键帧资产**（motion3 曲线） | 资产是「死」的：只有录制的瞬间才动，资产之间、语音之间、待机时全是「静态」——机械感的最大来源 |
| A3 | **情绪 = 离散标签/小向量**（开心/害羞） | 情绪被压成「开/关」，无法表达「微微不安地开心」这种连续状态 |
| A4 | **回合 = 基本时间单位**（每回合调度动作） | 只关心「这句话配什么动作」，不关心「这 3 分钟里角色怎么活着」 |
| A5 | **确定性 = 同输入同输出** | 确定性被当作「测试便利」，没有变成「自然度保证」 |
| A6 | **角色 = 参数容器**（被动接收写入） | 身体没有「记忆/惯性/情绪场」，只有参数寄存器 |

> **这些假设共同塑造了一个「木偶」模型：指令驱动、离散、静止、无身体。
> 真正的突破不是优化木偶的提线，而是把木偶变成演员。**

---

## Part 1. 三大范式转移（核心发散）

### S1｜指令 → 意图：LLM 从"提线木偶师"变"导演"

**现在**：LLM 输出 `play "挥手" {speed:1.2}`——一条**命令**（必须知道资产目录、覆盖参数、时序）。
**转变为**：LLM 输出一个**意图潜伏向量**（连续、低成本、语义化）——它不用知道资产目录，只要「表达此刻想要什么」。

```ts
/** LLM 每回合只输出这个（+文本，文本流向 TTS 成为语音脊梁） */
interface IntentLatent {
  energy: number;       // 0..1 总体能量/活跃度（驱动节奏、幅度）
  warmth: number;       // -1..1 亲近感
  dominance: number;    // -1..1 主导/服从
  playfulness: number;  // 0..1 玩闹度
  formality: number;    // 0..1 正式度
  focus: number;        // 0..1 注意力（对方/环境/自己）
  // N 维可扩展（任务相关轴：说服/安慰/讲题…）
}
```

**关键**：意图是**目标状态**，不是即时命令。角色身体以时间常数**趋向**这个目标，而不是被命令「跳」过去。

**为什么更好**：
- **容错**：意图错了只是「情绪/节奏略偏」，不会崩——连续错误平滑降级，不需拒绝/回退/重试
- **LLM 负担骤降**：不必知道 50 个资产名+覆盖——从「动作编导」降为「做自己」。DSL/库目录从 LLM 上下文里消失
- **涌现**：多个意图维度同时存在（既想亲近又想玩闹）→ 身体自然混合，而不是「一次只能演一个动作」

### S2｜资产 → 动力学：身体是"活"的

**现在**：动作 = 预录关键帧曲线，插值播放。
**转变为**：身体 = 一组**动力学运动控制器**（呼吸/体态/视线/微表情/手势/重心），每个控制器是一个**带惯性与弹簧-阻尼的小系统**，恒常运行（60fps），被意图+情绪场持续调制。

```ts
/** 运动控制器：身体的最小动力单元（确定性：种子化噪声 + 解析积分） */
interface MotionController {
  sem: string;                        // 绑定语义层
  target(state, intent, emotion, prosody, t): number;   // 目标值
  gains(state, intent, emotion): { kP: number; kD: number; amp: number; noise: number };
  step(dt: number, seed: SeededRandom): void;           // 弹簧-阻尼积分
}

// 内置控制器（全部 60fps 恒常运行、确定性、模型无关）
BreathController        // 呼吸：情绪呼吸频率/幅度调制（兴奋→浅快）
PostureController       // 体态：dominance→挺直/蜷缩；energy→前倾
GazeController          // 视线：focus→看向对方/看向远处/眼珠微动；turn-taking
MicroExpressionController // 微表情：emotion 场 → 眉/嘴角 1-3% 幅度微动
GestureController       // 手势：prosody 能量包络 → 说话时手势时机/幅度（SemGes 模式）
WeightShiftController   // 重心：恒常微移（粒度秒级）
IdleFidgetController    // 无意识小动作：摸发/整理衣角（低频、稀疏触发）
```

**为什么更好**：
- **消灭「静态感」**：待机、语音间、资产间——身体永在动。这是「活」与「木偶」的分水岭
- **自然度来源是物理不是资产**：呼吸/惯性/衰减产生真实感，几乎零资产成本
- **预留运动先验升级位**：控制器是一阶动力系统；将来可把 `gains()` 换成**学习的解码器**（SMP 扩散先验 / Learned Motion Matching，Ubisoft 已验证生产可用），SDK 核心仍零 ML 依赖（可插拔）

### S3｜回合 → 连续体：时间不是回合，是连续流

**现在**：LLM 每回合出一次指令 → 调度器播一段。
**转变为**：一个**连续的时间模型** + **三层继承**（对照机器人学层次控制，LCB/Hi-VLA 已验证）：

```
┌─ Deliberative（LLM，回合边界，~100ms-秒级）───────────────┐
│  更新：意图潜伏 + 情绪场 + 记忆/人格；产出文本→TTS          │
├─ Reactive（确定性，10-30Hz，事件驱动）────────────────────┤
│  消费：回合切换/抢话打断/语音事件 → 重新瞄准控制器+混合权重  │
├─ Reflex（确定性，60fps，无事件）──────────────────────────┤
│  运动控制器 + 音频脊梁（prosody 调制）+ 物理——永不停         │
└───────────────────────────────────────────────────────┘
```
- **LLM 只在回合边界被调用**（分层里最上层、最慢）——彻底移出关键路径
- 第一跳（Reactive+Reflex）连"缓存化行为选择"都不需要——它们本来就该一直在跑

## Part 2. 新运行时架构：The Living Actor

```
                    ┌──────────────────────────────┐
  用户输入/事件 ───► │  Deliberative (LLM, 回合边界)  │
                    │  意图潜伏 + 情绪场 + 记忆/人格   │◄─ 文本→TTS
                    └──────────────┬───────────────┘
                                   │ IntentLatent + EmotionField
                                   ▼
                    ┌──────────────────────────────┐
                    │  Reactive (10-30Hz, 确定性)    │
                    │  engagement clock + turn state│
                    │  controller 重瞄准 + 混合权重   │
                    └──────────────┬───────────────┘
                                   ▼
                    ┌──────────────────────────────┐
   SpeechTimeline ─►│  Reflex (60fps, 确定性)        │
   (audio/prosody) │  运动控制器群 + 物理 + 种子噪声   │
                    └──────────────┬───────────────┘
                                   ▼  每个 sem 的连续值
                    ┌──────────────────────────────┐
                    │  语义层映射 → 求值管线(10.3)    │
                    │  【情绪场调制】→物理→override    │
                    └──────────────┬───────────────┘
                                   ▼
                           ParameterSink（宿主渲染）
```
> **核心：意图进了身体，身体自己会动。** 指令通道（关键帧资产）降级为「签名时刻」的**可选**香料：
> 当导演明确要「演一个大幅挥手」（叙事情节高点），才用 `act` 原语调用库——但**待机、对话、过渡全由身体担当**。

### 音频脊梁（Audio Spine，S2/S3 的放大镜）
- TTS → `SpeechTimeline { text, durationMs, audio?, visemes[], prosody[] }`
- `prosody`（能量/音高包络）**直接调制** GestureController 幅度/时机 + 微表情 + 头部节奏
- 效果：手势不是「每句话一个」，而是**跟着语音高低起伏自然涌动**——这是真人感的第二个分水岭
- 确定性：同音频+同种子 → 同调制

### 情绪场（连续，非标签）
```ts
interface EmotionField { valence: number; arousal: number; dominance: number; }
// 不用预定义「开心=1.0」，而是连续场持续调制控制器增益与呼吸
// 例：arousal↑ → 呼吸浅快、手势幅度↑、微表情活跃
//     valence↓ → 体态蜷缩、视线回避、动作放缓
```
- 情绪场是**身体的状态**，不是「播放哪个表情」。表情资产只用于极端时刻的**加强**

### 记忆/人格（连续性的底座，参照 Generative Agents）
```ts
interface PersonaState {
  identity: immutable traits;            // 性格固定根
  episodicMemory: recent episodes;       // 短时记忆（衰减）
  relationship: { affinity; history };   // 关系（慢变、持久）
}
```
- 回合边界 LLM 读写；Reactive 层只消费情绪场/意图——身体不需要「记得」，只需要「感觉对」

## Part 3. 为什么它更优（对着项目自己的目标打）

| 目标 | v0.1/v0.2（指令框架） | v3.0 活体演员 |
|---|---|---|
| **LLM 可靠性** | 输出 50 资产目录里精确选中+覆盖；错了拒绝/重试 | 输出 6 维意图+情绪，错了只是「情绪偏一点」——连续容错 |
| **自然度** | 静态待机 + 一动作一句 | 身体恒在呼吸/眨眼/重心/微表情；手势随韵律涌动 |
| **延迟** | 第一跳 = 缓存行为选择（仍需事件触发） | 身体一直在动，LLM 只在回合边界——关键路径彻底清除 LLM |
| **确定性** | 同输入同输出（可测） | 同输入同输出（可测）+ **自然度不变量可测**（无 jitter/越界/跳变） |
| **模型无关** | 语义层 ✓ | 语义层保留 ✓（控制器绑定 sem，仍无裸 PARAM_*） |
| **宿主无关** | ParameterSink ✓ | ParameterSink 保留 ✓ |
| **LLM 上下文** | 资产目录 + kinds + 覆盖规则（重） | 6 维意图 + 情绪场（轻）——上下文成本骤降 |
| **测试** | 黄金 IR→轨迹 | 黄金（意图+情绪+音频+种子）→轨迹，且可写「自然度断言」 |

**一句话**：v0.1/v0.2 解决的是「让 LLM 可靠地发指令」；v3.0 解决的是「让身体可靠地活着」。
前者让模型不崩，后者让角色活。

## Part 4. 落地路径（保持项目一切优点，分阶段）

| 序 | 阶段 | 内容 | 是否破坏现有 |
|---|---|---|---|
| 1 | **A1 控制器基底** | 实现 MotionController 群（呼吸/体态/视线/微表情/重心/手势）+ 确定性积分 + 种子 | 不破坏：在 Reflex 层下方，可独立跑 |
| 2 | **A2 意图/情绪入口** | IntentLatent + EmotionField 类型；先用手写规则把意图映射到控制器增益（v1 无 ML） | 替换 LLM 输出：从 IR → 意图（不兼容，但 LLM 面更简单） |
| 3 | **A3 音频脊梁** | SpeechTimeline.prosody → 手势/微表情调制 | 保留 v0.2 的 viseme（E4），升级为全 prosody 调制 |
| 4 | **A4 指令通道降级** | keyframe 资产保留为 `act` 签名香料（可选），默认身体自立 | 不破坏：语言 A/资产仍有效，只是不再是主角 |
| 5 | **A5 记忆/人格** | PersonaState + 回合读写 | 叠加，不破坏 |
| 6 | **B1 学习先验（可选）** | 控制器 `gains()` 可换学习解码器（SMP/相位插值）—— SDK 核心仍零 ML 依赖 | 可插拔，默认确定性 |

> **保持的资产**：语义层/manifest（模型无关）、ParameterSink（宿主无关）、确定性+种子（可测）、语言 A 创作层（做签名资产）、安全/内容底线。
> **替换的**：LLM 输出形态（指令→意图）、运行时主引擎（动画播放→运动控制器）、时间模型（回合→连续体）。
> **降级的**：P4 创作模式（LLM 写运动曲线）→ 更边缘；关键帧资产 → 可选香料。

## Part 5. 风险与权衡（诚实清单）

1. **「活体」的失控风险**：运动控制器让角色「总是动」，若增益调参不当会显得「多动症/抽搐」。
   → 对策：控制器幅度有上限、情绪场有饱和、干跑可审查「自然度不变量」（无高频振荡/越振幅）。
2. **确定性 vs 复杂动力学**：弹簧-阻尼系统若用数值积分，不同帧率结果略不同。
   → 对策：固定步长积分（如 50Hz 子步）+ 注入时钟/种子——保持黄金测试。
3. **「意图潜伏」的语义校准难**：6 维意图→控制器增益的映射需要调参。
   → 对策：v1 用可解释规则（每轴直接对应等比增益），v2 再考虑学习；评估集（E7）记录调参回归。
4. **失去「精确动作控制」**：导演不能说「第三帧抬手 30 度」这种话（那是木偶）。
   → 对策：这是**有意的取舍**——精确控制交给 `act` 签名通道（少用），连续自然交给身体（多用）。对话场景 99% 不需要精确控制。
5. **工程量大**：控制器群 + 双层（Reactive/Reflex）比单个 scheduler 复杂。
   → 对策：A1 可独立成包 `packages/actor`，与现有 renderer 解耦，先干跑后接 renderer。

## Part 6. 附：范式对照总结

```
木偶范式（v0.1/v0.2）      →    活体演员范式（v3.0）
─────────────────────────────────────────────────
LLM 发指令                    LLM 表达意图
关键帧资产                   运动控制器（动力学）
离散标签情绪                 连续情绪场
回合调度                     连续时间体 + 三层
「同输入同输出」               + 「自然度不变量」
角色是参数容器                角色是身体（会呼吸/感受/惯性）
```

> **最终判断**：v0.1 的语义层与确定性是对的，继续保有；但「LLM 输出指令驱动资产」这个**核心范式**是可被代替的——更优的方案是**「LLM 出意图 + 身体出运动」**。这不是锦上添花，而是从「木偶」到「生命」的跃迁。
>
> *本文档为发散提案，供评审——若认可 S1/S2/S3 方向，建议先做 A1（控制器基底）干跑验证自然度增益，再决定替换路径。*
